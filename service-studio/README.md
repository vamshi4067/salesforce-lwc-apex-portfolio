# Service Studio — Salesforce LWC & Apex

Two fictional business workflows with real open-source Lightning Web Components, a public browser demo and corresponding Salesforce platform source. This release replaces the previous customer-support case demo.

## Run locally

Requires Node 22 or newer.

```sh
npm ci
npm test
npm run build
python3 -m http.server 8080 --directory dist
```

Visit http://localhost:8080. Use HTTP rather than opening the HTML file directly.

## What to try

**Quote & discount approval**

Evergreen Home is upgrading two properties. Edit quantities, add or remove products and change the discount. With the default basket, subtotal is $9,680 and the 15% discounted total is $8,228.

1. Set discount to 10% and submit: approved automatically.
2. Start a new draft, set 10.01% and explain the discount: pending manager approval.
3. Use the explicitly simulated manager controls to approve or reject with a note.
4. Try a missing justification, fractional quantity or discount above 30%.
5. Submitted quotes are locked; start another draft to make changes.

**Field-service booking**

Choose heating repair, an installation survey or annual maintenance. The next five dates are generated relative to the browser session; all demo times are local to the browser. Availability filters by technician skills.

1. Select a date and technician/time, then confirm using fictional contact details.
2. The occupied slot disappears, and the confirmation appears in session appointments.
3. Cancel the appointment: its time returns to availability.
4. Try confirming with no slot or an invalid email.

Switching views preserves form state. Reset reloads the page and clears this tab’s data. No emails are sent.

## Publish on Netlify

**Ready-built upload:** extract `Service-Studio-Netlify-v2.zip` and upload its contents (the folder containing `index.html`) at https://app.netlify.com/drop while signed in. The site runs without a Salesforce login. Assign your preferred site name after publication.

**Git build:** import `service-studio` as the repository base directory (or publish this folder as its own repository). `netlify.toml` sets build `npm run build`, publish `dist`, Node 22. Include the lockfile. No Salesforce credentials or environment variables are required.

The source download is generated by each build. The public site includes Source code and How it works views.

## Runtime boundaries

- Public: actual LWC components, static hosting, asynchronous in-memory adapter. No browser calls to a Salesforce org.
- Salesforce: separate platform LWCs call Apex and persist records in custom objects. Apex cannot execute on Netlify.
- Booking uses a custom slot model. It does not demonstrate Salesforce Field Service optimization, travel-time routing or licensed scheduling APIs.
- Quote approval uses a custom state machine and permission, not Salesforce native Approval Process metadata or CPQ.
- Browser manager controls demonstrate a role; they are not authentication.

## Salesforce sandbox setup

The `salesforce` folder contains an API 62.0 SFDX project. Use a fresh Developer Edition org or sandbox. Do not use production for this demo.

```sh
cd salesforce
sf org login web --alias service-studio
sf project deploy start --target-org service-studio --source-dir force-app --test-level RunSpecifiedTests --tests QuoteStudioControllerTest --tests BookingStudioControllerTest
sf org assign permset --name Service_Studio_User --target-org service-studio
sf org assign permset --name Service_Studio_Manager --target-org service-studio
sf apex run --file scripts/seed.apex --target-org service-studio
```

Add `salesQuoteStudio` and `fieldBookingStudio` to an App or Home page in Lightning App Builder and activate it. Assign `Service_Studio_User` to demo users and add `Service_Studio_Manager` only to reviewers. The seed script creates five days of slots in the executing Salesforce user’s time zone. Run it once; repeated runs would create duplicate availability rows. Provision new slots as dates expire.

The objects use public read/write sharing for a shared sandbox demo. These are educational controllers and simplified data models, not a production CPQ or dispatch system. Before production, restrict object sharing and editing, enforce invariants on all record entry paths, move catalog and thresholds to managed configuration, add record-level approval assignments, idempotency, audit retention, lifecycle management and full permission-matrix tests. The included permission sets allow direct record editing for sandbox inspection; controller validations apply to the component call path.

Salesforce deployment, Apex compilation, test coverage and actual lock-contention behavior must be verified in an authenticated org. Local Node or browser tests do not establish Apex correctness. Existing org rules can affect deployment and DML.

## Source map

- `src/modules/c/app`: shell, view navigation, architecture notes and source viewer.
- `quoteBuilder`: reactive quote inputs and reviewer UI.
- `appointmentBooking`: service/date filters, slot selection, confirmations and cancellation.
- `workflowService`: public catalog, validation, cent-based arithmetic and in-memory async mutations.
- `salesforce/force-app/main/default/classes`: controllers and Apex tests.
- `salesforce/force-app/main/default/objects`: quote, slot and booking metadata.
- `salesforce/force-app/main/default/lwc`: independent Salesforce platform components.
- `tests/workflows.test.mjs`: real business-rule tests including concurrent slot requests.

## Optional browser verification

With Playwright installed separately (`npm install --no-save playwright` and `npx playwright install chromium`), start the HTTP server and run `node tests/browser-smoke.mjs`. It checks totals, line edits, approval/rejection, booking/cancellation, source/download and responsive overflow, and saves screenshots under `verification`. `BASE_URL`, `SCREENSHOT_DIR`, `CHROMIUM_EXECUTABLE` and `PLAYWRIGHT_MODULE` can override the local defaults.
